# Tag and Link Conventions

## Links
Use links for concepts, people, projects, papers, methods, datasets, constructs, and claims.

Examples:
- `[[Generative Echo Chamber Effect]]`
- `[[Conversational Information Foraging]]`
- `[[Ziang Xiao]]`
- `[[Voice Echo Chamber — Cognitive Susceptibility]]`

## Tags
Use tags for filtering and graph color, not for every topic.

Recommended tags:
- `#project`
- `#paper`
- `#card`
- `#problem`
- `#lens`
- `#research-question`
- `#observation`
- `#person`
- `#organization`
- `#study`
- `#evaluation`
- `#experiment`
- `#pseudocode`
- `#software-feature`
- `#writing`
- `#method/hci`
- `#method/nlp`
- `#status/seed`
- `#status/active`
- `#status/waiting`
- `#status/done`

## Properties
Use properties when you want tables or filters.

Common properties:
- `type`
- `status`
- `stage`
- `project`
- `projects`
- `methods`
- `themes`
- `problems`
- `lenses`
- `thesis_track`
- `tracker_status`
- `last_reviewed`
- `next_milestone`
- `read_status`
- `venue_target`
- `deadline`

## Status Markers
Use `tracker_status` for project workflow state:
- `:this_is_fine:` IRB
- `:glitch_crab:` Pre-registration
- `:ziang-xiao:` Need review
- `:claude:` Experiments
- `:dart:` Final Stage
- `:x:` Didn't make it

## When To Create a Card
Create a card when a term, claim, mechanism, or design pattern appears in more than one place, or when it might become a paper idea later.

## When To Create a Problem, Lens, or Research Question
- Problem: high-level durable issue that multiple projects address.
- Lens: reusable theory or analytic frame used to interpret several projects.
- Research question: atomic question that can be answered by one or more studies, evaluations, or software systems.
